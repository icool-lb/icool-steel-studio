# خطة إعادة هيكلة منصة iCOOL Steel Studio v3
## مع تفاصيل Google Earth + سير المدقق الهندسي + الدمج

---

## المبدأ الحاكم
**كل حساب = دالة صافية (Pure Function) لا تلمس DOM ولا THREE.
كل رسم = مُصيِّر (Renderer) يقرأ نتيجة الحساب فقط.
كل تقرير = مكوّنات مشتركة تُجمَّع مرة واحدة.**
هذا هو العلاج الجذري للتكرار الثلاثي الذي رصده التدقيق.

## 2) تفاصيل تكامل Google Earth (محدّدة تنفيذياً)

المنصة تستورد KML اليوم؛ التوسعة المطلوبة على 4 مسارات:

| المسار | التنفيذ | التكلفة |
|---|---|---|
| **A. تصدير KML من المشروع** (الأولوية 1) | زر «تصدير إلى Google Earth» يولّد Placemark لكل مصفوفة: `<Polygon>` للسطح، أعمدة كـ `<Model>` أو LineString بارتفاع h، مسار الشمس كـ gx:Track اختياري، والظل كمضلّع متعدد الألوان لساعة معيّنة | يوم واحد |
| **B. الموقع الجغرافي التفاعلي** | Leaflet + طبقة صور Esri World Imagery (بلا مفتاح) افتراضياً، وGoogle Maps JS API اختيارياً إدخال المستخدم مفتاحه الخاص. النقر على الخريطة يحدّث lat/lon ويقلب KML import إلى إحداثيات WGS84 مباشرة | يومان |
| **C. الارتفاعات والتضاريس** | Elevation API مجاني (Open-Elevation أو endpoint يحدده المستخدم) → رفع منسوب المبنى ودراسة ظلال التضاريس المحيطة (هاوية/جبل) التي تغيّر الشروق الحقيقي | يوم |
| **D. الشمال الحقيقي من Earth** | موجود عبر KML — يُستكمل بزر «محاذاة البوصلة مع صورة القمر الصناعي»: يدور المخطط تلقائياً حتى يطابق حواف المباني في الصورة (عامل ارتباط بسيط على حواف Polygon مقابل تدرّج الصورة) | 2 يوم |

قاعدة: لا يُضاف أي سطر يتطلب مفتاح Google مدفوعاً إلا كخيار اختياري يفعّله المستخدم بمفتاحه.

## 3) سير «المستشار الهندسي المدقّق» (Checker Workflow)

يُطبَّق على **كل** مخطط و3D قبل أن يكون قابلاً للطباعة:

1. **كتلة أساس الحساب (CALC BASIS)** إلزامية أسفل كل لوحة:
   المرجع (EN 1991-1-4 §… / IEC 60898) + المعاملات المستخدمة + حدود الصلاحية
   (بحر ≤ X م، ارتفاع ≤ Y م، فئة تضاريس II…) — صراحةً لا ضمنياً.
2. **ختم فحص رقمي**: كل لوحة تولّد `hash` من مدخلاتها؛ أي تعديل بعد «اعتماد المدقق»
   يجعل الختم أحمر «معدَّل بعد الاعتماد» ويُلغى توقيع `SIGN_IMG` تلقائياً.
3. **جدول مراجعات (Revision Table)** على كل Sheet: R0/R1/R2 بالتاريخ والوصف والراسم والمدقق.
4. **بوابة التقرير**: لا يعمل زر طباعة إذا `VAL.ok === false` إلا بعد
   checkbox صريح: «أتحمّل مسؤولية تجاوز ملاحظات: …» تُكتب نصاً وتُطبع في التقرير.
5. **فحوص المدقق الإنشائية الجديدة** (calc/checks.js):
   - انبعاج الأعمدة: `N/(χ·A·fy)` بطول فعّال من ارتفاع الكتف (k=1.0–2.0 حسب التثبيت).
   - انبعاج الوتر العلوي: LTB ببحر التضليع الفعلي لا بحر الجمالون كاملاً.
   - بليتة القاعدة: انحناء اللسان (cantilever method, EN 1993-1-8) + قص اللحام.
   - زلزال: قوة جانبية مكافئة = 0.10–0.25 W (حسب منطقة المستخدم) في توليفة مستقلة.
6. **فحوص المدقق الكهربائية الجديدة**:
   - هبوط الجهد: ΔV% لكل مسار (DC سلاسل، بطارية، خرج محوّل، دوائر نهائية) بحد 3%/5%.
   - الانتقائية: تدرّج تصنيفات القواطع (رئيسي ≥ 1.6× الفرعي) وإلا تحذير أحمر.
   - تصنيف SPD (T1 إذا كان مبنى بصواعق + PV على سطح مرتفع).

## 4) الدمج الفعلي في هذا التسليم

### أ) صفحة As-Built (جاهزة الآن)
`panel-asbuilt-studio.html` تعمل مستقلة بلا أي تبعية. خطوات الدمج في المنصة:
1. انسخ محتوى `<script>` الخاص بها في `js/asbuilt/panel-studio.js` وأضف تبويباً
   جديداً `CATS.push(['asbuilt','منفّذ'])`.
2. زر «JSON للدمج» يملأ `EQP` عبر `icoolImportAsBuilt(json)` الموجود في
   `deye-realism-pack.js` — القطع تظهر فوراً في غرفة الكهرباء 3D بمقاساتها الحقيقية.
3. المخطط الناتج (SVG) يُضاف تلقائياً في نهاية تقرير الغرفة كملحق «كما نُفِّذ».

### ب) حزمة Deye (جاهزة الآن)
`deye-realism-pack.js` — أضفه بعد تعريفات المنصة ثم نفّذ `DEYE_PATCH.patchPlatform()`.
- مفاتيح invModel الجديدة تملأ القائمة تلقائياً.
- ⚠ **تنبيه المدقق**: كل بُعد معلَّم `approx` يجب مطابقته مع Datasheet Deye الرسمي
  (SUN-xxK-SG04LP3 / SG01HP3 / BOS-GM) قبل طباعة أي لوحة — الجدول جاهز للتدقيق
  خلاياه سطراً سطراً.

### ج) Shop DWG
- `sheets/panels.js` الحالي يولّد SVG → أضف `io/dxf.js::exportPanelDXF(panel)` يكتب
  نفس الهندسة بوسوم ENTITIES (LWPOLYLINE/LINE/TEXT) — نفس مصدر البيانات، صيغتان.
- التابلوهات المنفّذة من صفحة As-Built تُصدَّر DXF بنفس الدالة فلا يتكرر الرسم.
